# 不足与优化改进计划

> 诚实清单:当前系统「可交付」但不是「完美」。按优先级列出已知不足、技术债与改进路线。

---

## 一、功能层不足(P2 需求 backlog)

| # | 项 | 现状 | 建议 |
| --- | --- | --- | --- |
| 1 | 凭证附件上传前端控件缺失 | 后端接口就绪(白名单/10MB),录入页未挂上传 UI,列表仅显示张数 | P2 首批补齐,工作量小 |
| 2 | 工资核算模块未含 | 报销+凭证覆盖了大部分费用场景,工资表计算/个税未做 | 二期:工资表导入生成凭证即可满足多数小企业 |
| 3 | 现金流量表 | 未实现完整版(需科目现金流辅助维度) | 可先出「简化版」:货币资金科目发生额按对方科目分类 |
| 4 | 金税/开票对接 | 发票为登记台账模式 | 对接需要税控资质,保持手工导入是务实选择 |
| 5 | 多币种 / 汇兑损益 | 未支持 | 有外贸客户需求时再做 |
| 6 | 合并报表 / 多账套汇总 | 账套完全隔离无合并 | 集团场景再说 |
| 7 | 报表导出格式单一 | 余额表 CSV;BS/IS 仅打印 | 补 xlsx 导出(带样式)与 PDF 直出 |
| 8 | 移动端 App / 小程序 | 手机浏览器自适应已可用 | 高频审批场景可做轻量小程序 |

## 二、工程与架构债

| # | 项 | 风险 | 改进方案 |
| --- | --- | --- | --- |
| 1 | **数据库变更用 `db push` 无迁移基线** ⚠️ | 生产升级不可追溯、无法回滚 | 切换 `prisma migrate dev/deploy`,建立 migration 历史(交付前建议立即做) |
| 2 | 无 Docker Compose | 部署依赖本机环境 | 编排 pg+server+web 三容器,docker compose up 即起 |
| 3 | 无 CI 流水线 | 回归靠手动跑 E2E | GitHub Actions:tsc + 单测 + e2e(pg service)三步门禁 |
| 4 | 无 API 文档站点 | 前后端协作靠口头 | 接入 @nestjs/swagger,DTO 已规范成本低 |
| 5 | E2E 未覆盖并发场景 | 极端下凭证号可能撞号(事务内 max+1) | 加唯一约束兜底已防脏数据;可改 SELECT FOR UPDATE 或序列 |
| 6 | 大表无虚拟滚动 | 数万行分页查询本身安全,前端长列表滚动略卡 | el-table-v2 或分页默认 20 条已缓解 |
| 7 | Dashboard echarts 全量引入(~1MB chunk) | 首屏加载偏慢 | 改 echarts/core 按需注册(Line/Bar/Grid/Tooltip),预计减 60% |
| 8 | 日志只入库不落盘轮转 | 长期运行表膨胀 | 加 retention 清理任务或接入文件日志 |
| 9 | 单元测试覆盖面窄(纯函数) | 服务层逻辑靠 E2E 兜底 | 核心服务(结转/红冲)补带内存 Prisma mock 的用例 |
| 10 | 外接卷开发路径含空格中文 | 个别工具链偶发兼容问题 | 正式部署放常规路径 |

## 三、安全加固(生产上线前必做)

1. **改默认口令**:所有演示账号密码、`.env` 的 JWT 密钥与 DATABASE_URL
2. **HTTPS**:Nginx 反代 + TLS,禁 3100/5173 直接外露
3. **限流**:登录接口加 IP 限流(目前仅错登锁定账号,无限流)
4. **刷新令牌轮换**:refresh 时旧 token 作废机制可再加严格一点
5. **备份异地化**:当前备份下载到本地,建议加 OSS/S3 上传选项
6. **审计增强**:导出类操作也记日志

## 五、已知边界声明(对客户的预期管理)

- 本系统面向**中小企业单组织**,不做集团合并、不做上市公司合规模块
- 发票为台账管理,不承诺税务合规性审查(税率勾选正确性由用户负责)
- 折旧仅平均年限法(工作量法/双倍余额递减未做)
- 数据量设计目标:单账套 ≤50 万凭证/年 内性能无感
