## 2. 数据模型(20+ 表)

### 2.1 实体关系总览

```
Tenant(账套)─┬─ Period(期间,唯一 year+month,status 1进行中/2已结)
              ├─ Subject(科目,自关联 parentId,isLeaf/category1-6/direction/assist JSON)
              ├─ UserTenant / UserRole / UserRoleBinding(RBAC 三表)
              ├─ InitialBalance(期初行:subjectCode+direction+amount+partner?)
              ├─ Voucher(凭证)─┬─ VoucherEntry(分录:subject/debit/credit/辅助核算维度)
              │                  └─ Attachment(附件)
              ├─ ArapBill(应收应付四类单据)── ArapWriteoff(核销流水,多对多桥)
              ├─ Invoice(发票,io 销项/进项,taxRate/taxAmount)
              ├─ BankAccount(资金账户↔1002 明细科目)/ StatementLine(对账单行)
              ├─ ExpenseClaim(报销头)— ExpenseClaimItem(明细)— ApprovalRecord(流转记录)
              ├─ FixedAsset(资产卡)— DepreciationRecord(月折旧台账)
              └─ OperationLog(操作审计:before/after JSON)
```

### 2.2 关键约束与设计点

| 表 | 设计要点 |
| --- | --- |
| Voucher | 唯一约束 `(tenantId, periodId, word, no)`;`sourceType`:1手工/3折旧/4结转/5红冲;`redForVoucherId` 红冲回链防重复红冲;status 0草稿/1待审核/2已记账/3作废 |
| VoucherEntry | lineNo 行号;金额 Decimal(18,2);辅助核算 `departmentId/partnerId/projectId` 可空外键;结算方式 settleType/settleNo 仅资金类科目使用 |
| Subject | `assist` JSON 标记需要的辅助维度 `{partner?,department?,project?,settle?}`,子科目继承父级;category 1资产/2负债/3权益/4成本/5收入/6费用 |
| Period | 唯一 `(tenantId, year, month)`;closedBy/closedAt 记录结账人;结账自动补建下期 |
| ExpenseClaim | status 0草稿/1待部门审批/2待总经理审批(≥阈值)/3待财务复核/4待付款/5已付款/6已驳回/7已撤回 |
| OperationLog | 统一拦截器写入,记录 before/after 快照、IP、UA |

金额字段全部 `Decimal(18,2)`;服务层运算前 `Number()` 转换、写库前 `toFixed(2)` 回转,规避 JS 浮点误差。

## 3. 认证与权限

- **JWT 双令牌**:accessToken(2h)+ refreshToken(7d),payload 含 `uid/tid/perms[]`;切换账套 = `/auth/switch-tenant` 重签两个令牌
- **RBAC**:权限码目录化(GET /perms-catalog 返回全量码),角色持有码集合;`@Perm('voucher:audit')` 装饰器 + PermsGuard 校验;isSuper 直通
- **多租户**:TenantGuard 从 token 解出 tid 注入 request;所有查询强制带 tenantId;业务表无全局唯一冲突
- **密码**:bcrypt(10 rounds);连续错登锁定;修改密码需旧密码验证

权限码清单(19 个):dashboard:view / md:manage / ledger:init / ledger:view / voucher:create / voucher:audit / closing:execute / report:view / arap:manage / invoice:manage / fund:manage / expense:create / expense:approve / expense:pay / asset:manage / system:user / system:role / system:log / system:backup。

## 4. 凭证引擎(ledger/voucher.service)

### 4.1 状态机与规则映射

```
create(status=0) ─ submit ─> 1 ─ approve ─> 2 ─ red-flush ─> 新凭证(sourceType5)
   ▲                          │                
   │ reject(reason)           │ cancel-audit   
   └──────────────────────────┘(期间未结 & 无下游引用)
void: 0→3 作废;delete: 仅草稿物理删除
```

- R1 保存校验:≥2 行、每行金额>0、逐行借贷互斥、合计借=贷、摘要必填、科目必须末级且启用
- R6 已记账禁 PUT/DELETE;R7 approve 时校验 createdBy ≠ 当前用户;R8 cancel-audit 校验期间未结 + 无下游(被红冲/被核销引用则拒绝)
- 辅助核算强校验:按科目 assist 定义检查 partner/department/project 必填;settle 类科目要求结算方式
- 凭证号:`word + 期间内递增 no`,事务内 max+1

### 4.2 红冲实现
读取原凭证分录 → 金额两侧取反生成新凭证(sourceType=5,redForVoucherId=原id,memo 自动注明「红冲:原凭证号」)→ 走正常提交审核流。重复红冲由「存在 status∈{0,1,2} 的 redForVoucherId 回链」拦截。

## 5. 余额计算模型(balance.service)

**设计原则:不存余额快照,实时聚合。**

```
periodSeq(year, month) = year*12 + month        // 期间比较退化为整数
computeBalances(tenantId, endSeq, startSeq?) 返回 Map<subjectId, {
  openDebit/openCredit,       // 期初 = InitialBalance + Σ(分录 ≤ startSeq-1)
  debit/credit,               // 本期发生 = Σ(startSeq..endSeq)
  ytdDebit/ytdCredit,         // 年累计发生
  closeDebit/closeCredit      // 期末 = 期初±发生(方向归一后落一侧)
}>
```

三条参数化 SQL(`$queryRawUnsafe`)分别求:≤endSeq 累计、年内发生额、区间发生额;服务层合并。
**自然余额归一化**:`naturalClose(bal, direction)` 把带方向科目的净额折叠到其自然方向一侧(借方科目出现贷差时落在贷方并返回负数语义),供报表与试算平衡统一口径。

## 6. 报表引擎(report.service)

### 6.1 公式模型(存 ReportFormula 表)

```jsonc
// bal:科目余额项。s 支持前缀展开('1002' 匹配自身+'100201'等叶子)与伪科目
{ "t": "bal", "terms": [{ "s": ["3103","3104"], "coef": 1 }, { "s": ["@pl"], "coef": 1 }] }
// act:窗口发生额(side D/C),IS 口径排除 sourceType=4 结转凭证
{ "t": "act", "s": ["5001"], "side": "C" }
// rows:已计算行的线性组合
{ "t": "rows", "items": [{ "key": "gross_profit", "coef": 1 }] }
```

`@pl` 伪科目 = Σ类别5叶子自然余额 − Σ类别6叶子自然余额,即**未结转损益**,使资产负债表在任何时点都平衡(未分配利润行 = 3103/3104 + @pl)。

### 6.2 BS 平衡校验
构建完成后比较 total_asset 与 total_liab+total_equity,返回 `balanceCheck {balanced, asset, liabilityEquity}` 随报表下发,前端渲染平衡徽标。

### 6.3 利润表双口径
本期列:startSeq=endSeq 单期间;年累计列:year*12+1 起。两列均排除结转凭证,反映真实经营发生额。

## 7. 期末处理(closing.service)

### 7.1 结账检查清单
`checklist()` 返回四项 blocking 检查:上期已结账(起始期豁免)/ 无草稿及待审凭证 / 损益已结转(plActivityGroups 按「科目净发生额≠0」分组判断,排除结转凭证)/ 试算平衡(末级科目 close 借贷合计差<0.01)。close() 前置强校验全过才允许,失败抛 ERR.CLOSING_CHECK_FAILED 并附明细。

### 7.2 结转损益算法
```
GROUP BY subjectId, category, departmentId, partnerId, projectId   -- 维度随行携带
HAVING SUM(debit) <> SUM(credit)
→ 类别5: natural=c-d 借记冲减收入;类别6: natural=d-c 贷记冲减费用
→ remain = ΣD - ΣC;remain>0 贷记 3103(盈利),否则借记(亏损)  -- 保证严格平衡
→ 生成 sourceType=4 「转」字凭证(submit:true 直接待审核)
```
重复结转由「本期已存在 sourceType=4 凭证」拦截。

### 7.3 折旧计提(平均年限法)
```
monthly = round2(originalValue × (1 − salvageRate) / lifeMonths)
remaining = round2(totalDep − accumulatedBefore)          // 提足即停
当月新增(acquiredDate > 月末)不提;depAmount = min(monthly, remaining)
按 depExpenseSubjectId 汇总借方(携带部门维度),贷方 1602 累计折旧
生成 sourceType=3 凭证 + DepreciationRecord 台账(含 voucherId 回链)
```
单元测试覆盖:35000×95%/36=923.61、提足边界。

## 10. 安全设计

1. bcrypt 密码;JWT HS256,密钥 `.env`(交付默认值,**生产必改**)
2. 全接口 JWT + 租户隔离;权限码最小分配;出纳无审核权、制审分离为硬约束
3. 参数校验 class-validator DTO 白名单;SQL 全部参数化($queryRawUnsafe 绑定参数)
4. 上传白名单 jpg/png/pdf ≤10MB,随机文件名
5. 敏感操作 OperationLog before/after 留痕(IP/UA)
6. 备份文件服务端生成,blob 带 Token 鉴权下载,不暴露目录
7. 建议:生产部署置于 Nginx 反代之后启用 HTTPS;`.env` 权限 600
