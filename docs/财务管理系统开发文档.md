## 1. 项目概述

### 1.1 项目背景

中小企业普遍存在财务人员少、一人多岗、账务处理依赖 Excel 或手工记账的现状,常见痛点包括:

- 凭证、账簿、报表割裂,数据需要反复搬运,易出错;
- 应收应付、发票登记散落在多张表格中,催收与付款提醒缺失;
- 费用报销靠纸质单据+微信审批,事后难以入账追溯;
- 老板看不到实时经营数据,月底才知道盈亏。

本系统旨在为 50~500 人规模的中小企业提供一套**轻量、易用、合规**的一体化财务管理平台,覆盖"建账 → 凭证 → 账簿 → 报表 → 往来/资金/报销辅助管理"的完整闭环。

### 1.2 项目目标

| 目标 | 说明 |
| --- | --- |
| 合规 | 按《小企业会计准则》输出标准凭证、账簿与三大报表 |
| 易用 | 会计 30 分钟内可完成期初建账;支持凭证模板、常用摘要库 |
| 一体化 | 业务单据(报销/应收应付/发票)一键生成记账凭证 |
| 安全 | RBAC 权限、操作留痕、数据备份恢复机制完备 |
| 可演进 | 单企业私有化部署起步,架构预留 SaaS 多租户改造空间 |

### 1.3 系统边界

**本期范围内(In Scope)**:基础档案、期初建账、凭证管理、账簿查询、三大财务报表、期末结账、应收应付、发票登记、资金日记账与银行对账、费用报销审批流、固定资产、管理看板、系统管理。

**本期范围外(Out of Scope,P2 及以后另行评估)**:工资核算模块、金税盘/税控发票自动开具对接、电子会计档案归档、多语言、合并报表、预算管理与成本核算(作业成本法)、与外部 ERP(Odoo/金蝶/用友)的数据迁移工具。

### 1.4 术语定义

| 术语 | 定义 |
| --- | --- |
| 凭证(Voucher) | 记录经济业务、明确借贷方向的记账依据,是全系统的数据源头 |
| 分录(Entry) | 凭证中的一行借贷记录,一行只能记借方或贷方之一 |
| 过账(Posting) | 将已审核凭证的金额汇总到科目余额/发生额的过程(本系统采用实时汇总+期末结账锁定策略) |
| 结账(Closing) | 锁定某一会计期间,禁止再修改该期间数据 |
| 辅助核算 | 在科目维度之外按客户/供应商/部门/项目等维度拆分统计 |
| 红冲 | 用负数(红字)凭证冲销原凭证错误金额 |

## 2. 需求分析

### 2.1 用户角色与权限(RBAC)

| 角色 | 主要职责 | 关键权限 |
| --- | --- | --- |
| 系统管理员 | 用户与权限维护、参数配置、备份 | 全部系统管理功能,**不含业务数据修改权** |
| 财务主管 | 建账、结账、审核凭证、报表复核 | 科目/期初维护、凭证审核/反审核、结账/反结账、全部报表 |
| 会计 | 凭证录入、往来核销、折旧计提 | 凭证增删改(仅草稿)、账簿查询、报表查看 |
| 出纳 | 收付款登记、银行对账 | 日记账、对账单导入勾兑;**无凭证审核权(不相容岗位分离)** |
| 普通员工 | 提交报销、查询本人报销进度 | 仅本人报销单 |
| 部门负责人 | 审批本部门报销 | 本部门报销单审批 |
| 总经理/老板 | 查看经营看板与报表 | 只读:看板、报表、大额支出明细 |

> 内控要求:出纳与审核岗位强制分离;同一用户不得同时拥有"凭证录入"与"凭证审核"权限(可在角色配置中硬性约束,见 §7 规则 R12)。

### 2.2 核心业务流程

```
期初建账 ──► 录入/生成凭证 ──► 审核 ──► 记账生效 ──► 账簿/报表实时更新
   │              ▲                                  │
   │              │ (报销单/发票/应收应付/折旧 自动生成凭证)   │
   │              └──────────── 业务模块联动              ▼
   └── 开账 ──────────────────────────────────► 期末结账(锁定期间)
```

**主流程说明**

1. **建账**:管理员创建账套,财务主管导入标准科目表、设置辅助核算、录入期初余额并试算平衡;
2. **日常**:会计录入凭证或由业务单据自动生成凭证草稿 → 财务主管审核 → 审核后即计入账簿(过账实时化);
3. **月末**:计提折旧、摊销、结转损益(系统提供一键向导生成对应凭证)→ 核对试算平衡 → 财务主管执行结账;
4. **出表**:资产负债表、利润表随时可查;现金流量表在结账时按收付实现制辅助归类生成。

## 3. 总体设计

### 3.1 技术选型(推荐方案)

| 层次 | 选型 | 理由 |
| --- | --- | --- |
| 前端 | Vue 3 + TypeScript + Vite + Element Plus + Pinia + ECharts | 组件生态成熟,后台管理系统开发效率高,国内团队上手快 |
| 后端 | Node.js 20 LTS + NestJS(TypeScript)+ Prisma ORM | 前后端同语言、类型贯通;模块化架构清晰 |
| 数据库 | PostgreSQL 16 | 事务可靠,DECIMAL 精确运算,jsonb 存储辅助核算灵活扩展 |
| 缓存/会话 | Redis 7 | 登录态、接口防重、报表缓存 |
| 文件存储 | 本地磁盘(MinIO 兼容接口预留) | 附件(发票影像/报销凭证)低成本起步 |
| 认证 | JWT(Access + Refresh Token) | 无状态、前后端分离友好 |
| 部署 | Docker Compose 单机部署(Nginx + API + DB + Redis) | 符合中小企业 IT 条件,一台云主机即可运行 |
| 定时任务 | NestJS Schedule(结账检查、到期提醒、备份) | 轻量,无需额外中间件 |

> 备选方案(若团队已有 Java 积累):Spring Boot 3 + MyBatis-Plus + MySQL 8,功能设计完全不变,仅技术栈替换。**此为决策点 D1,见 §14。**

### 3.2 系统架构图

```
┌────────────────────────── 浏览器(PC 优先,响应式适配平板)──────────────────────────┐
│  Vue 3 SPA:登录/工作台 │ 基础设置 │ 凭证中心 │ 账簿报表 │ 往来资金 │ 报销中心 │ 固定资产 │
└──────────────────────────────────────┬───────────────────────────────────────────┘
                                       │ HTTPS (Nginx 反向代理 + 静态托管)
┌──────────────────────────────────────▼───────────────────────────────────────────┐
│                        NestJS API 服务(模块化单体)                                │
│  Auth/RBAC │ 基础档案 │ 凭证引擎(核心)│ 账簿汇总服务 │ 报表引擎 │ 业务单据 │ 任务调度 │
└───┬──────────────┬───────────────┬────────────────┬────────────────┬─────────────┘
    │              │               │                │                │
┌───▼───┐   ┌──────▼─────┐   ┌─────▼─────┐   ┌──────▼──────┐  ┌────▼────┐
│Postgres│   │   Redis    │   │ 本地文件存储│   │ 定时任务进程 │  │ 导出服务  │
│(主+备) │   │ 会话/缓存   │   │ 附件/影像  │   │ 备份/提醒    │  │ Excel/PDF│
└────────┘   └────────────┘   └───────────┘   └─────────────┘  └─────────┘
```

**架构原则**

- **模块化单体**:一期不做微服务,以 NestJS Module 划分限界上下文,保证中小团队可维护性;
- **凭证引擎为核心**:所有业务模块(报销/应收应付/折旧)只产生"凭证草稿",统一进入凭证引擎审核记账,保证账务口径唯一;
- **余额实时汇总**:每次凭证审核通过后增量更新科目余额表(发生额/余额),避免报表全表扫描;反审核/红冲做对称冲减,并提供"余额重算"修复工具。

## 4. 功能模块详细设计

### 4.1 基础设置(system + masterdata)

**4.1.1 账套与期间**

- 支持多账套(如母公司/分公司各一套账),用户需选择账套后操作,数据严格按账套隔离;
- 会计期间按自然月自动生成年历(1–12 月 + 年结),期间状态:`未开始 / 进行中 / 已结账`;
- 启用会计年度与启用期间在建账时确定,不可晚于首张凭证日期。

**4.1.2 会计科目**

- 预置《小企业会计准则》标准一级科目(1001 库存现金 … 6901 以前年度损益调整,约 60+ 个);
- 科目编码采用 **4-2-2 分级**(一级 4 位,每级追加 2 位,最长 8 级),下级科目编码必须以父级开头;
- 属性:方向(借/贷)、是否末级、是否数量核算、是否辅助核算(客户/供应商/部门/项目,多选)、是否现金流量项目关联科目;
- 已使用的科目不允许删除,只能停用;停用科目不再出现在新凭证选单中。

**4.1.3 往来单位与辅助档案**

客户/供应商档案:编码、名称、税号、开户行账号、联系人、信用期(天)、信用额度、状态;部门/项目/员工为轻量表,用于辅助核算与报销归属。

**4.1.4 凭证模板与常用摘要(P1)**

保存分录组合(科目+方向+默认金额公式),录入时一键带出;常用摘要按使用频次排序推荐。

### 4.2 期初建账(F05)

1. 选择启用期间(如 2026-01);
2. 按末级科目录入期初余额(方向借/贷),支持 Excel 导入;
3. 辅助核算科目需展开到具体客户/供应商录入明细期初,系统自动向上汇总;
4. 试算平衡:借方合计 = 贷方合计方可"启用账套";启用后期初锁定,只能通过"期初调整凭证"修正。

### 4.3 凭证管理(F06–F08,系统核心)

**4.3.1 凭证要素**

头:凭证字+编号(按凭证字+月度连续编号,如 记-202602-0001)、日期、附单据数、制单人、审核人、摘要。
体:多行分录 {行号、摘要、科目(末级)、借方金额、贷方金额、辅助核算明细、结算方式/票据号(资金类科目)}。

**4.3.2 状态机**

```
草稿(Draft) ──提交──► 待审核(Pending) ──审核──► 已记账(Posted)
   ▲                      │                          │
   └──── 驳回 ◄───────────┘                          ├── 反审核(需回退到 Pending,且期间未结账)
                                                     └── 红冲(生成等额反向红字新凭证,原凭证保留)
```

- 只有 `草稿` 可修改/删除;`已记账` 凭证任何字段不可改,错账一律红冲或补充更正;
- 作废仅允许对 `草稿/待审核` 使用,作废凭证编号保留不回收(审计要求)。

**4.3.3 录入体验要点**

- 科目选择支持编码/名称模糊搜索;输入科目后自动记忆方向;
- 借贷合计实时显示差额,不平衡禁止保存;
- 支持"上一张/下一张/复制凭证/插入分录/删除分录/键盘流录入"(数字小键盘友好);
- 附件:每张凭证最多 20 个,单个 ≤10MB,类型 jpg/png/pdf。

### 4.4 账簿查询(F09)

| 账簿 | 口径 |
| --- | --- |
| 总分类账 | 一级科目逐期:期初余额 + 借方发生 − 贷方发生(或反向)= 期末余额 |
| 明细账 | 末级科目逐笔列示凭证分录,含摘要/对方科目 |
| 科目余额表 | 全部末级科目本期期初/借/贷/期末四栏,支持逐级折叠、辅助核算穿透 |
| 日记账 | 1001/1002 科目的序时账,出纳视图含结算方式与票据号 |

所有账簿支持:期间切换、包含未记账(草稿)开关、Excel/PDF 导出、双击联查凭证原文。

### 4.5 财务报表(F11/F12)

**取数逻辑示例(小企业会计准则)**

| 报表项目 | 取数公式 |
| --- | --- |
| 资产负债表·货币资金 | 1001+1002+1012 期末借方余额 |
| 资产负债表·应收账款 | 1122 期末借余 − 坏账准备(1231)贷余,负数重分类至预收?否——小准则按余额直填并附说明 |
| 利润表·营业收入 | 6001+6051 本期贷方发生额 |
| 利润表·净利润 | 收入类贷方发生合计 − 成本费用类借方发生合计 − 所得税费用 |
| 现金流量表 | 以 1001/1002/1012 对方科目的现金属性映射(销售/采购/支付职工/支付税费…),结账时批量归类,支持手工调整 |

- 报表支持月/季/年、累计数、同期对比;
- 报表公式以**配置表**存储(项目 ↔ 科目区间/方向/公式类型),便于后续适配《企业会计准则》(决策点 D4 相关);
- 未结账期间报表标注 "未经审核" 水印。

### 4.6 期末处理(F13)

1. **计提折旧向导**:按固定资产卡片逐项计算当月折旧,汇总生成一张转账凭证(借:制造费用/管理费用等,贷:累计折旧);
2. **结转损益向导**:将全部损益类科目余额结转至 3103 本年利润,自动判断方向,生成结转凭证;
3. **结账检查清单**:存在未审核凭证 / 损益未结转 / 试算不平衡 / 上期未结账 时阻断结账;
4. **反结账**:仅财务主管,且下一期间无任何凭证时才允许;全程写审计日志。

### 4.7 应收应付(F14)

- 单据类型:应收单/收款单/应付单/付款单(也可由发票登记直接生成应收/应付);
- **核销**:收款单 ↔ 应收单 多对多核销,部分核销记录剩余额;
- 账龄分析:按单据到期日划分 0–30/31–60/61–90/90+ 天,逾期高亮;
- 到期前 N 天站内消息+邮件提醒(阈值可配);
- 收付款单保存后自动生成凭证草稿(借:银行存款 / 贷:应收账款 等)。

### 4.8 发票管理(F15)

- 台账字段:方向(进/销)、开票日期、发票号码、对方单位、品名、金额、税率、税额、价税合计、状态(正常/作废/红冲)、关联凭证号;
- 提供 Excel 批量导入(识别主流电子发票导出格式);
- 统计:本月销项税额 − 进项税额 = 应纳增值税预估(税务辅助雏形,P2 深化);
- 与应收应付联动:销项发票可一键生成应收单。

### 4.9 资金管理(F16)

- 日记账自动来源:凭证中含 1001/1002 且填写了结算方式的分录;
- **银行对账**:导入银行流水 Excel/CSV(模板映射)→ 按金额+日期(+票号)自动勾兑 → 人工调整 → 输出余额调节表(企业账面余额 ± 未达账项 = 银行对账单余额);

### 4.10 费用报销(F17)

**流程**:员工填报(费用类型/金额/事由/附件/归属部门项目)→ 部门负责人审批 → (金额 ≥ 阈值时)总经理审批 → 财务复核 → 出纳付款 → 自动生成凭证草稿。

- 审批流配置化:按"金额区间 × 费用类型"路由,节点支持会签/或签;
- 抄送通知走站内信 + 邮件;超 48h 未审批自动催办;
- 报销标准控制:差旅住宿/交通标准按职级配置,超标需填理由并可被驳回;
- 付款完成前报销单可撤回;全程状态可追溯,员工端仅见本人单据。

### 4.11 固定资产(F18)

- 卡片:资产编号、名称、类别、购置日期、原值、残值率(默认 5%)、使用年限(月)、折旧方法(**一期仅平均年限法**)、使用部门、存放地点、状态;
- 月折旧额 =(原值 − 原值×残值率)÷ 使用年限,当月增加当月不提、当月减少当月照提;
- 处置:出售/报废生成清理凭证(固定资产清理过渡科目);
- 提供资产台账、折旧汇总表、到期提醒。

### 4.12 报表中心与看板(F19)

老板视角一屏展示:本月收入/成本/费用/净利润及环比、现金流余额、应收总额与逾期额、应付总额、TOP5 费用科目、近 12 月收支趋势图;数据 T+0 来自余额汇总表,只读。

### 4.13 系统管理(F22)

- 用户管理:启用/禁用、密码重置、强制首次改密;
- 角色/菜单/按钮三级权限;数据权限按账套隔离(一期不做部门级数据权限,预留);
- 操作日志:登录、关键写操作(谁/何时/IP/改了什么,差异留痕);
- 备份:每日凌晨 pg_dump 全量备份保留 30 天,支持手动备份与一键恢复演练文档;
- 参数配置:公司信息、税率默认值、报销审批阈值、提醒阈值。

## 5. 数据库设计

### 5.1 设计约定

## 6. API 接口设计

### 6.1 规范约定

- RESTful + 统一前缀 `/api/v1`,JSON over HTTPS;
- 统一响应:`{ "code": 0, "message": "ok", "data": {...}, "traceId": "..." }`;非 0 为业务错误码(如 `40001 参数错误`、`40301 无权限`、`42001 借贷不平`);
- 认证:`Authorization: Bearer <JWT>`;刷新令牌 `/auth/refresh`;
- 分页:`?page=1&pageSize=20`,返回 `{total, page, pageSize, list}`;
- 所有写接口幂等:客户端携带 `X-Idempotency-Key`。

## 7. 关键业务规则与校验

| # | 规则 | 校验时机 |
| --- | --- | --- |
| R1 | 每张凭证至少 2 行分录;Σ借方 = Σ贷方 > 0;同行借贷互斥且不同时为零 | 保存/提交 |
| R2 | 凭证日期必须落在所属期间内,且该期间状态为"进行中" | 保存 |
| R3 | 分录科目必须是末级且启用状态的科目 | 保存 |
| R4 | 标注辅助核算的科目,分录必须携带对应辅助明细 | 保存 |
| R5 | 凭证号按 凭证字+期间 连续分配,删除/作废不回收号段 | 后端分配 |
| R6 | 仅"草稿"可编辑/删除;"待审核"仅可被驳回;"已记账"只能红冲 | 状态机拦截 |
| R7 | 审核人与制单人不得为同一用户 | 审核 |
| R8 | 反审核要求:期间未结账 且 该凭证未被下游单据引用 | 反审核 |
| R9 | 结账前置:上期已结账、无未审核凭证、损益已结转、试算平衡、无未勾兑重大差异(提示不阻断) | 结账 |
| R10 | 反结账要求:下一期间不存在任何凭证 | 反结账 |
| R11 | 科目发生额不为零或存在下级时不可删除,仅可停用 | 删除 |
| R12 | 角色互斥:同一用户的权限集合不得同时包含"凭证录入"与"凭证审核"(出纳不得审核) | 角色保存 |
| R13 | 期初启用要求:Σ借 = Σ贷,且启用日 ≤ 首张凭证日 | 启用账套 |
| R14 | 折旧规则:当月新增不提、当月减少照提;提足后自动停止 | 折旧向导 |
| R15 | 所有金额计算使用 DECIMAL,四舍五入保留两位,分位误差 ≤ 0.01 由尾差调整行消化(结转损益场景) | 引擎层 |

## 8. 安全设计

| 类别 | 措施 |
| --- | --- |
| 身份认证 | bcrypt(cost≥10)存密码;JWT 双令牌(access 2h / refresh 7d 轮换);连续失败 5 次锁定 15 分钟;支持强制改密与密码复杂度策略 |
| 授权 | RBAC 三级(菜单/按钮/接口注解守卫);接口层二次鉴权,不信任前端隐藏 |
| 传输 | 全站 HTTPS(TLS1.2+),HSTS;内网部署同样启用自签证书 |
| 注入/XSS/CSRF | ORM 参数化;全局输入校验(class-validator);富文本/附件名过滤;SameSite Cookie + CSRF Token(表单场景) |
| 文件安全 | 附件白名单类型+魔数校验、重命名存储、独立域/路径访问,禁止执行权限 |
| 敏感数据 | 税号/银行账号界面脱敏展示;备份文件 AES-256 加密落盘 |
| 审计 | 登录日志 + 关键写操作 before/after 快照;日志只读保留 ≥ 3 年 |
| 数据安全 | 每日全量备份 + WAL 归档(可选),异地对象存储副本;恢复演练手册 |
| 会话安全 | 单设备互踢可选;登出即吊销 refresh token;敏感操作(结账/反结账/删除凭证)二次确认+操作密码 |

## 10. 部署方案
