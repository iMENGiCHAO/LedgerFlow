## 三、关键技术决策(为什么这么做)

1. **编译后运行而非 tsx**:tsx/esbuild 不输出 `design:paramtypes` 构造器元数据,NestJS 依赖注入在运行时拿到空参数导致崩溃。最终方案:`tsc` 编译后 `node dist/main.js`,dev 调试才用 tsx 跑纯逻辑脚本。
2. **端口 3100**:3000 被本机常驻 GUI 占用(CSRF_FAILED 假响应极具迷惑性),`.env` 固定 PORT=3100。
3. **无余额快照表的实时余额**:余额=期初行+已过账分录聚合,三段 SQL(累计≤endSeq / 年初至今 / 区间发生额)。避免结转/反结账时的状态同步地狱,代价是查询稍重——中小企业的数据量下完全可接受。
4. **periodSeq = year*12+month**:把期间比较退化为整数比较,所有跨期 SQL 简化。
5. **报表公式存库而非写死**:ReportFormula 表存 JSON 表达式(`bal` 科目余额项 / `act` 发生额项 / `rows` 组合行),换科目体系或改报表只需改数据。
6. **红冲而非删除**:已记账凭证只能生成两侧金额取反的新凭证(sourceType=5,redForVoucherId 回链),符合审计要求。
7. **结转损益按「科目+辅助核算」分组**:管理费用等科目强制部门辅助核算,冲销行必须携带原维度否则校验不过;净额方向修正为「借方富余贷记本年利润」,±0.01 尾差自动消化。
8. **E2E 先行**:先写断言再修缺陷,44 条断言成为回归安全网,后续每次改动跑一遍即可放心。

## 四、踩坑与修复实录(精华部分)

### 环境类
| # | 现象 | 根因 | 解法 |
| --- | --- | --- | --- |
| 1 | pnpm install 超时 | 外接卷 IO 慢 | `--config.fetch-timeout` 重试;前端改用本地 store `~/.pnpm-fm-store` |
| 2 | Prisma 构建脚本被忽略 | pnpm 安全策略 | `pnpm-workspace.yaml` 配 `allowBuilds: true`(五个包) |
| 3 | Prisma schema 校验连环报错 | 缺反向关系/可选外键写成必填关系 | Python 批量补丁脚本修复 |
| 4 | 启动报 `getAllAndOverride of undefined` | tsx 无装饰器元数据(见决策 1) | tsc 编译运行;另注意残留 tsx 进程占端口要先 pkill |
| 5 | curl 3000 返回 CSRF_FAILED | 端口被 GUI 占用 | 改用 3100 |
| 6 | pnpm 11 不读 package.json 的 onlyBuiltDependencies | 版本行为变化 | `CI=true pnpm approve-builds --all` |
| 7 | 备份失败 pg_dump 版本不匹配(16 vs 服务器 17) | PATH 里是旧版;且 `SHOW server_version` 不支持列别名,首版解析列名 `v` 落空 | 按 `/usr/local/opt/postgresql@<major>/bin/pg_dump` 探测;用 `Object.values(rows[0])[0]` 取值 |
